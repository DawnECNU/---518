# 轻问卷：基于 MongoDB 的在线问卷系统（阶段二）

阶段二在阶段一可运行系统上增加了可复用题目、共享、版本历史、个人题库和跨问卷统计。界面仍使用 Flask 服务端模板，不依赖前端构建工具。

GitHub 仓库：https://github.com/DawnECNU/---518

## 已实现功能

- 用户注册、登录、退出；密码使用 Werkzeug 加盐哈希保存。
- 用户只能管理自己创建的问卷；公开链接可供其他登录用户填写。
- 创建问卷、设置说明、匿名策略、重复填写策略和截止时间。
- 发布问卷、复制公开链接、关闭问卷。
- 单选题、多选题、文本填空题、数字填空题。
- 必答、选项数量限制、文本长度限制、数字范围与整数限制。
- 可配置跳转：单选选项、多选包含某选项、多选数量、数字区间、跳转到结束。
- 逐题保存答案；未提交答卷可继续填写；支持多人同时填写。
- 整卷统计与单题统计：选项分布、回答人数、文本答案、数字平均值/最小值/最大值。
- 独立创建并保存可复用题目，一份题目资料包含一个逻辑题目和多个不可变版本。
- 草稿问卷可直接选择已有题目、他人共享题目或“我的题库”中的题目。
- 固定版本快照：问卷选择某个版本后，题目库的后续修改不会改变该问卷；发布问卷继续禁止改题。
- 版本历史显示父子关系与来源版本，支持根据旧版本创建新的当前版本。
- 按用户名把题目共享给其他用户；共享用户可以直接复用，修改时会自动复制为自己的私有题目。
- 查看逻辑题目被哪些问卷使用，并在题目详情中进入跨问卷统计。
- 跨问卷按所选版本汇总同一题目的单题、多选、文本或数字结果。
- 启动时自动把阶段一题目补齐为逻辑题目和 v1 版本，保留原题目 ID，因此旧答卷无需迁移。

## 运行环境

- Python 3.10+（本机验证版本为 3.12.8）
- MongoDB 6.0+（本机验证版本为 8.3）
- 依赖：Flask 3.1.3、PyMongo 4.18.1

## 启动

1. 启动 MongoDB。

   已有本机 MongoDB：

   ```powershell
   mongod --dbpath C:\path\to\mongo-data
   ```

   或使用 Docker：

   ```powershell
   docker compose up -d mongo
   ```

2. 在当前阶段二目录安装依赖并启动应用。

   ```powershell
   cd "C:\Users\Lenovo\Desktop\当代数据管理系统第一次大作业\大作业一第二阶段的代码"
   python -m venv .venv
   .\.venv\Scripts\Activate.ps1
   pip install -r requirements.txt
   $env:MONGO_URI = "mongodb://127.0.0.1:27017"
   $env:MONGO_DB_NAME = "survey_phase1"
   python app.py
   ```

3. 打开 `http://127.0.0.1:5000`，先注册账号。

首次启动会自动创建题目模板、版本、共享和题库集合，安装 JSON Schema 校验器并建立索引，不需要手工执行建表脚本。继续使用阶段一的数据库名即可在原数据上自动升级；如需纯演示数据，可把 `MONGO_DB_NAME` 改成其他名称。

## 配置

可通过环境变量配置，示例见 `.env.example`：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `SECRET_KEY` | 开发用默认值 | Flask 会话签名密钥，部署时务必修改 |
| `MONGO_URI` | `mongodb://127.0.0.1:27017` | MongoDB 连接串 |
| `MONGO_DB_NAME` | `survey_phase1` | 数据库名；沿用该名称可在阶段一数据上自动迁移 |
| `SURVEY_BASE_URL` | 空 | 复制问卷链接时使用的外部地址 |

## 关键规则

### 跳转

- 每道题的 `jump_rules` 是数组，按顺序匹配，第一条命中规则生效。
- 没有规则命中时，进入题目顺序中的下一题。
- 规则目标只能是当前题目之后的题目，或 `target = null` 表示结束问卷，避免循环跳转。
- 被跳过的题目不进入 `path`，因此不会被当作“必答题未回答”。

### 匿名

填写者仍需登录，这是初始需求中“填写问卷的人需要先登录”的要求。选择匿名时：

- 答卷标记 `anonymous = true`；
- 统计页面不展示任何填写者身份；
- 数据库保留内部 `user_id`，仅用于访问控制、恢复未提交答卷和执行“每人限一份”限制。

### 编辑限制

问卷发布后，题目、选项和跳转规则锁定，避免已提交答卷与题目结构不一致；截止时间仍可在关闭前调整。草稿阶段修改题目时会创建新版本，原先引用旧版本的问卷快照保持不变。

### 版本与共享

- 版本文档创建后不覆盖，`parent_version_id` 记录版本链，`source_version_id` 记录恢复或复制来源。
- 每个问卷题目独立保存一份内容快照，答题和统计仍使用问卷题目 ID，因此已提交答卷不会因版本更新而失去对应关系。
- 题目所有者可以按用户名共享题目。被共享用户只能使用，不能修改原题；在问卷中修改时会生成归自己所有的新题目。
- 撤销共享只阻止后续选题，不影响已经加入问卷的版本快照。
- 个人题库是用户与逻辑题目的关联，共享题目也可以加入自己的题库。
