# 系统说明（阶段一）

## 1. 项目概况

本项目是一个基于 MongoDB 的简化在线问卷系统，功能定位类似“问卷星”或 Google Forms。注册用户可以创建问卷、添加不同类型的题目、设置校验规则和条件跳转规则，发布后通过公开链接邀请其他登录用户填写；问卷创建者可以查看整卷统计和单题统计。

系统采用 Flask 服务端渲染架构，不依赖前端构建工具。页面、样式、后端路由、业务逻辑和 MongoDB 数据访问均位于同一项目中，便于部署和课程演示。

## 2. 用户角色

| 角色 | 主要能力 |
| --- | --- |
| 问卷创建者 | 注册登录、创建问卷、添加和编辑题目、配置跳转、发布/关闭问卷、设置截止时间、查看统计 |
| 问卷填写者 | 登录后通过公开链接进入问卷、按顺序答题、按规则跳转、恢复未提交答卷、检查并提交答案 |

一个账号可以同时承担两种角色。创建者只能管理自己创建的问卷，但可以通过公开链接填写其他用户的问卷。

## 3. 功能范围

| 功能模块 | 已实现内容 |
| --- | --- |
| 账号 | 注册、登录、退出、密码哈希、注册时间、会话管理 |
| 问卷管理 | 标题、说明、匿名策略、重复填写策略、发布、截止时间、关闭、公开链接 |
| 题目管理 | 单选、多选、文本填空、数字填空；必答设置和各类约束 |
| 跳转 | 单选选项、多选包含、多选数量、数字区间、跳转结束；规则保存在 MongoDB |
| 填写 | 逐题保存、自动跳转、错误提示、草稿恢复、提交前检查、匿名、重复填写限制 |
| 统计 | 整卷统计、单题统计、选项次数、回答人数、文本答案、数字平均值和极值 |
| 数据完整性 | MongoDB JSON Schema、唯一索引、查询索引、后端二次校验 |

## 4. 系统架构

```text
浏览器
  │ HTTP 请求 / 表单提交
  ▼
Flask 应用 app.py
  ├─ 路由与请求参数解析
  ├─ 登录、会话、CSRF 和权限检查
  ├─ 调用 survey_logic.py 处理业务规则
  ├─ 通过 db.py/PyMongo 读写 MongoDB
  └─ 使用 templates/ 生成 HTML
          │
          ▼
       MongoDB
       ├─ users
       ├─ surveys
       ├─ questions
       └─ responses
```

系统没有使用 ORM。`db.py` 在应用启动时创建 `MongoClient`，选择数据库，并把数据库对象保存到 Flask 的 `app.extensions["mongo_db"]`。各路由通过 `mongo.get_db()` 获取数据库对象，直接对集合执行 `find`、`insert_one`、`update_one` 等操作。

## 5. 技术选型

| 层次 | 技术 | 选择原因 |
| --- | --- | --- |
| Web 后端 | Flask 3.1 | 轻量、路由清晰、适合服务端模板和小型课程项目 |
| 数据库 | MongoDB 6.0+ | 文档模型适合保存嵌套选项、跳转规则和不同题型答案 |
| Python 驱动 | PyMongo 4.18 | 直接操作 MongoDB，便于展示数据库设计 |
| 页面模板 | Jinja2 | 与 Flask 集成，不需要额外前端构建流程 |
| 密码 | Werkzeug 加盐哈希 | 不保存明文密码 |
| 测试 | Python `unittest` | 标准库即可运行，便于课程环境复现 |

## 7. 主要业务流程

### 7.1 注册和登录

1. 用户提交用户名、密码和确认密码。
2. 后端检查用户名长度、空格、密码长度和两次密码是否一致。
3. 密码经 Werkzeug 生成加盐哈希后保存到 `users`。
4. 登录成功后，会话中保存用户 ID。
5. 每个请求根据会话中的用户 ID 重新加载用户对象。

### 7.2 创建、配置和发布问卷

1. 创建者在草稿状态填写问卷标题、说明、匿名策略、重复填写策略和可选截止时间。
2. 问卷保存到 `surveys`，初始状态为 `draft`，同时生成随机 `public_id`。
3. 草稿阶段可以添加、编辑题目以及配置跳转规则。
4. 发布前检查是否至少有一道题、截止时间是否仍然有效、跳转规则是否合法。
5. 发布后状态变为 `published`，题目和跳转规则锁定，避免已发布问卷结构变化。
6. 创建者可以在关闭前调整截止时间，或将问卷状态改为 `closed`。

### 7.3 填写问卷

1. 填写者先登录，再通过 `/s/<public_id>` 打开问卷介绍页。
2. 后端检查问卷状态和截止时间。
3. 开始填写时创建一份 `responses` 文档，记录第一题和空答案。
4. 每回答一题，后端解析答案、执行校验、计算下一题并立即保存。
5. 规则命中时跳到目标题；目标为 `null` 时进入提交检查页。
6. 提交时重新校验实际访问过的题目，然后把状态改为 `submitted`。

### 7.4 查看统计

1. 创建者进入统计页。
2. 后端查询该问卷中 `status = submitted` 的答卷。
3. 按题型分别计算选项次数、文本内容、数字平均值等。
4. 统计结果由已提交答卷自动生成，不保存重复的统计结果文档。

## 8. 运行环境与配置

### 8.1 环境要求

- Python 3.10+
- MongoDB 6.0+
- Flask、PyMongo
- Windows 环境建议安装 `tzdata`，确保 `ZoneInfo("Asia/Shanghai")` 可用

再打开另一个终端启动应用：

```powershell

python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

### 8.3 配置项

| 配置 | 默认值 | 作用 |
| --- | --- | --- |
| `SECRET_KEY` | 开发默认值 | Flask 会话签名，部署时必须替换 |
| `MONGO_URI` | `mongodb://127.0.0.1:27017` | MongoDB 地址 |

| `CSRF_ENABLED` | `True` | 是否启用表单 CSRF 防护 |

## 9. 安全与数据完整性

- 密码只保存 Werkzeug 加盐哈希，不保存明文。
- 会话 Cookie 设置 `HttpOnly` 和 `SameSite=Lax`。
- 所有写操作使用 POST，并验证 CSRF Token。
- 管理、编辑和统计操作均检查 `owner_id`，防止用户访问他人管理页面。
- 答卷页面根据当前用户 ID 检查答卷归属。
- MongoDB 使用 `$jsonSchema` 做字段类型和枚举校验。
- 用户名和公开链接建立唯一索引。
- 后端对表单和答案再次校验，数据库校验不能替代业务校验。
- 答案更新使用条件更新，检测当前题目是否已被其他页面改变。

## 10. 设计边界

阶段一明确采用以下边界：

- 跳转只允许前往当前题之后的题目或结束问卷，避免循环。
- 被跳转规则跳过的必答题不会进入 `path`，因此不会被误判为漏答。
- 问卷发布后不允许修改题目和跳转规则。
- 截止时间不会自动改变 `status`，而是参与“是否允许填写”的判断。
- 匿名填写仍然要求登录；内部保留 `user_id` 用于访问控制和重复填写判断，但统计不展示身份。
- 阶段一不包含题目删除、题目重排、密码找回、管理员后台和 JSON API。
