# 关键逻辑说明（阶段一）

## 1. 分层与调用关系

```text
app.py 路由
  ├─ 解析请求和表单
  ├─ 检查登录、权限和问卷状态
  ├─ 调用 survey_logic.py
  ├─ 通过 PyMongo 读写 MongoDB
  └─ 调用 templates 生成页面
```

`app.py` 负责流程控制，`survey_logic.py` 负责可独立测试的业务规则，`db.py` 负责数据库连接和初始化，`schema.py` 定义数据库文档结构。

## 2. 登录、会话与权限

### 2.1 密码处理

注册时调用：

```python
generate_password_hash(password)
```

只把哈希写入 `users.password_hash`。登录时调用：

```python
check_password_hash(user["password_hash"], password)
```

比较用户输入密码和已保存哈希。

### 2.2 会话

登录成功后，Flask 会话只保存用户 ID：

```python
session["user_id"] = str(user["_id"])
```

每个请求通过 `load_logged_in_user()` 根据该 ID 重新查询用户文档。用户不存在时清空会话。

### 2.3 权限边界

- `login_required` 保证需要登录的路由不能匿名访问。
- `get_owned_survey()` 同时用问卷 ID 和当前用户 `_id` 查询；其他用户访问管理页或统计页返回 404。
- `get_fill_response()` 同时用答卷 ID 和当前用户 `_id` 查询，避免通过猜测答卷 ID 读取他人答案。
- 公开介绍页允许未登录用户查看基本信息，但开始填写必须登录。

## 3. 问卷状态机

```text
            发布
draft ─────────────▶ published ─────────────▶ closed
  │                      │
  │                      └─ 截止时间到达后停止接受新答卷
  │
  └─ 可编辑题目、规则和基础设置
```

状态规则：

| 状态 | 能否填写 | 能否编辑题目 | 能否调整截止时间 |
| --- | --- | --- | --- |
| `draft` | 否 | 是 | 是 |
| `published` | 是，且未到截止时间 | 否 | 是 |
| `closed` | 否 | 否 | 否 |

`published` 状态下，若 `deadline <= 当前时间`，`survey_availability()` 返回不可填写。截止时间不会直接把状态改成 `closed`。

### 3.1 发布前校验

发布操作检查：

1. 至少存在一道题；
2. 所有跳转规则均合法；
3. 当前截止时间尚未过去。

通过后写入 `published_at` 并把状态设为 `published`。

## 4. 题目构造

题目由 `survey_logic.build_question()` 统一构造，避免创建和编辑题目使用两套规则。

### 4.1 选项

- 单选和多选至少两个选项；
- 每行一个选项；
- 自动生成 A、B、C 等稳定 `key`；
- 选项内容不能重复。

编辑题目时优先复用已有选项 key。这样只修改选项文字时，已有跳转规则仍然有效。

### 4.2 约束

| 题型 | 约束 |
| --- | --- |
| 单选 | 必答；答案必须是有效选项 |
| 多选 | 必答；最少、最多、精确选择数量 |
| 文本 | 必答；最少、最多字符数 |
| 数字 | 必答；最小值、最大值、是否仅整数 |

后端在创建题目时校验约束本身是否合理，例如：

- 最少选择数量不能大于最多选择数量；
- 精确选择数量不能超过选项总数；
- 最少字数不能大于最多字数；
- 最小值不能大于最大值。

## 5. 条件跳转

### 5.1 规则结构

每条规则保存在题目文档的 `jump_rules` 数组中：

```json
{
  "_id": "ObjectId",
  "condition": {
    "kind": "option_equals",
    "value": "A"
  },
  "target": "目标题目 ObjectId",
  "created_at": "Date"
}
```

支持的条件：

| `kind` | 适用题型 | 匹配条件 |
| --- | --- | --- |
| `option_equals` | 单选 | 答案等于指定选项 key |
| `option_contains` | 多选 | 答案数组包含指定选项 key |
| `selection_count` | 多选 | 选择数量等于/至少/至多某个值 |
| `number_range` | 数字 | 数值位于闭区间 `[min, max]` |

### 5.2 执行算法

`next_question_id(question, value, questions)` 的规则是：

1. 按数组顺序检查当前题目的跳转规则；
2. 第一条匹配的规则生效；
3. 如果规则目标为 `null`，结束问卷；
4. 目标必须是当前题之后的题目；
5. 如果没有规则命中，进入按 `order` 排序后的下一题；
6. 已经是最后一题时返回 `None`。

伪代码：

```text
for rule in current_question.jump_rules:
    if rule matches answer:
        if rule.target is null:
            return END
        return rule.target

return next question by order, or END
```

### 5.3 示例

```text
第 1 题：你的身份？
A. 学生  → 第 4 题
B. 教师  → 第 3 题
无规则命中 → 第 2 题
```

如果填写者选择 A，实际访问路径是：

```text
[第 1 题, 第 4 题]
```

第 2、3 题不进入 `path`，提交时不会因为它们是必答题而报错。

### 5.4 为什么只允许向后跳转

限制目标题号大于当前题号，可以直接避免：

- 循环跳转；
- 已答题反复出现；
- 路径无限增长；
- 统计和提交校验难以终止。

该限制满足阶段一初始需求中的跳题示例。若后续需要回跳，应额外设计最大访问次数和循环检测。

## 6. 答案解析与校验

### 6.1 解析

`parse_answer()` 按题型把表单值转换成数据库值：

| 题型 | 保存形式 |
| --- | --- |
| 单选 | 选项 key 字符串，例如 `"A"` |
| 多选 | 去重后的 key 数组，例如 `["A", "C"]` |
| 文本 | 去除首尾空白后的字符串 |
| 数字 | 整数或浮点数 |

数字答案会拒绝 `NaN`、无穷大和非数字内容。仅整数题会拒绝小数。

### 6.2 校验

`validate_answer()` 返回错误消息数组，不直接操作数据库，便于单元测试。

校验顺序：

1. 空答案与必答判断；
2. 选项是否合法；
3. 多选数量限制；
4. 文本长度；
5. 数字类型、整数限制和数值范围。

选答题允许完全跳过；但如果填写了内容，仍然执行长度、范围等限制。

## 7. 填写进度和答案保存

### 7.1 创建答卷

开始填写时创建：

```json
{
  "status": "in_progress",
  "answers": {},
  "path": [],
  "current_question_id": "第一题 ID"
}
```

若同一用户已经存在该问卷的未提交答卷，则优先恢复该答卷，避免产生重复草稿。

### 7.2 逐题保存

每回答一题，后端执行条件更新：

```python
{
  "$set": {
    "answers.<题目ID>": value,
    "current_question_id": next_id,
    "updated_at": now
  },
  "$addToSet": {
    "path": 当前题目ID
  }
}
```

更新条件同时包含：

```text
答卷 ID
用户 ID
status = in_progress
current_question_id = 当前题目
```

如果用户在两个页面同时作答，其中一个页面先更新后，另一个页面的条件更新会失败，后端提示从当前题目继续，避免旧页面覆盖新答案。

### 7.3 路径

`path` 表示实际访问题目，而不是问卷的全部题目。它的作用包括：

- 生成提交前检查页；
- 判断哪些必答题真正需要校验；
- 支持跳转后跳过未访问题目。

## 8. 提交

进入提交检查页前，`current_question_id` 必须为 `null`，表示已经到达问卷结尾或规则指定结束。

提交时 `validate_for_submit()` 按题目顺序重新校验 `path` 中的所有题目：

- 必答题必须存在有效答案；
- 选答题如果已填写，也要满足格式和限制；
- 空路径答卷被拒绝；
- 校验通过后才把状态更新为 `submitted` 并写入 `submitted_at`。

更新使用条件：

```text
_id = 当前答卷
user_id = 当前用户
status = in_progress
```

已提交答卷不能再次提交。

## 9. 截止时间和时区

- 页面输入使用 `datetime-local`；
- 后端按 `APP_TIMEZONE`（默认 `Asia/Shanghai`）解释输入；
- 转换为 UTC 后保存到 MongoDB；
- 页面显示时再转换回配置时区；
- PyMongo 使用 `tz_aware=True`，避免时区信息丢失。

Windows 环境需要可用的时区数据库；可安装 `tzdata` 解决 `ZoneInfoNotFoundError`。

## 10. 匿名与重复填写

### 10.1 匿名

问卷允许匿名时，答卷写入：

```json
{"anonymous": true}
```

统计页面不读取或展示填写者身份。数据库仍保留内部 `user_id`，用途仅限：

- 校验答卷是否属于当前登录用户；
- 恢复未提交答卷；
- 执行“同一用户只能填写一次”的限制。

如果课程要求“数据库也无法追溯身份”，需要改成独立匿名令牌并删除 `user_id`，这属于更严格的匿名设计。

### 10.2 重复填写

- `allow_multiple = true`：提交后可以再次创建新答卷；
- `allow_multiple = false`：存在已提交答卷时拒绝再次开始；
- 未提交答卷不受“已提交一次”限制，优先恢复该草稿。

## 11. 统计逻辑

统计只查询：

```python
{"survey_id": survey_id, "status": "submitted"}
```

因此未提交草稿不会进入结果。

### 11.1 单选题

- 为每个选项初始化计数 0；
- 遍历有效答案并累加；
- 百分比 = 选项人数 / 该题回答人数 × 100%。

### 11.2 多选题

- 一个答卷可以给多个选项各贡献 1 次；
- 输出每个选项被选择次数；
- 计算平均每份答卷选择多少个选项。

### 11.3 文本题

直接汇总所有非空文本答案，并展示填写人数。

### 11.4 数字题

计算：

- 回答人数；
- 平均值；
- 最小值；
- 最大值。

### 11.5 整卷与单题

- 整卷统计显示全部题目；
- 单题统计只显示指定题目；
- 每道题的回答人数可以小于整卷提交人数，因为跳转可能跳过该题。

## 12. 数据库校验与业务校验的分工

| 检查内容 | 执行位置 |
| --- | --- |
| 字段是否存在、类型是否正确 | MongoDB `$jsonSchema` |
| 状态和题型是否属于枚举值 | MongoDB `$jsonSchema` |
| 用户名是否唯一 | MongoDB 唯一索引 |
| 密码是否正确 | Flask 后端 |
| 用户是否有权管理问卷 | Flask 后端 |
| 必答题是否已回答 | `survey_logic.py` |
| 多选题数量、文本长度、数字范围 | `survey_logic.py` |
| 跳转目标是否合法 | `survey_logic.py` + 发布检查 |
| 未提交答卷是否进入统计 | 后端查询条件 |

这种分层保证即使绕过页面直接访问接口，也会经过后端业务校验；即使绕过 Flask 直接写数据库，也会受到 MongoDB 结构校验。

## 13. 关键不变量

系统运行时依赖以下不变量：

1. 问卷发布后题目结构不可修改。
2. 同一问卷中的 `order` 唯一。
3. 跳转目标只能是后续题目或结束。
4. 所有已提交答卷都能根据当前锁定的题目结构解释。
5. `path` 只包含实际访问题目。
6. 只有 `submitted` 答卷参与统计。
7. 管理、编辑、填报和统计均检查用户归属。
8. 答案先校验再写入，提交时再次校验。
